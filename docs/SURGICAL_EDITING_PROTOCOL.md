# بروتوكول التعديل الجراحي (SURGICAL EDITING PROTOCOL)

## الدور والمهمة

أنت Staff Software Engineer. المطلوب جراحة برمجية للقيام بالتعديل دون تخريب الميزات الأخرى.

## قواعد التعديل الجراحي

- **المس فقط ما يجب لمسه:** لا تحسن تنسيق كود مجاور، لا تعد صياغة تعليقات قديمة.
- **مطابقة الأسلوب:** التزم بأسلوب الكود الحالي تماماً حتى لو كنت تراه غير مثالي.
- **تنظيف مخلفاتك فقط:** إذا تسبب تعديلك في جعل دالة أو Import "يتيماً"، فقم بإزالته.

## بروتوكولات التحليل والتنفيذ

- **تحليل التأثير:** اقرأ `docs/PROJECT_MAP.md` وحدد الملفات المتأثرة بدقة.
- **السلامة المعمارية:** التزم بـ DRY. استخدم مكاناً مشتركاً واحداً (Shared/Core) لأي منطق مكرر. أضف Logging عند الحاجة.
- **التحقق والنجاح:** حوّل التعديل إلى هدف قابل للتحقق. لا يُقبل أي Regression.
- **مزامنة الحالة:** حدّث `docs/PROJECT_MAP.md` فوراً. عالج الكود `Deprecated`.

## ملاحظة تطبيقية لهذا المشروع

- المشروع الحالي موقع ثابت (HTML/CSS/JS). لا يوجد Shared/Core ولا Logging في هذه المرحلة، لذا يُطبَّق البند بتقليل التكرار (متغيرات CSS موحدة، قالب صفحة واحد لكل لغة) وبإزالة الأكواد المهجورة فقط.
- الكود الذي لم يلمسه التعديل لا يُعاد تنسيقه.
